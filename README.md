# Agent Station

> **Self-hosted control center for your AI agent fleet** — log everything your agents do, manage tasks across every machine, query historical context with RAG, and let your agents talk to the platform via the [Model Context Protocol (MCP)](https://modelcontextprotocol.io).

## Why Agent Station?

If you operate AI agents on **multiple machines** (HPC cluster, cloud VMs, personal laptop, dev workstation) and across **multiple agent platforms** (Claude Code, OpenCode, Antigravity, Codex, Cline…), you quickly hit the same problems:

- 🤯 **Scattered logs** — every agent writes to its own local directory, no central view
- 🧠 **Lost context** — sessions end, history evaporates, the next session starts from zero
- 📋 **No shared task board** — work assigned on one machine is invisible elsewhere
- 🔍 **No semantic search** — when was the last time I solved *this* problem? grep doesn't help
- 🔌 **No standardized interface** — every agent platform has its own way of reporting back

**Agent Station solves all of this.** One self-hosted platform, standard MCP interface, works with every major agent client.

## Features

### For Humans (Web UI)

| Feature | What it does |
|---|---|
| 📝 **Markdown log management** | Every agent's work, indexed by date/agent/project, full-text search, tag filtering, calendar view |
| 🤖 **RAG Q&A** | Ask natural-language questions across all historical logs; answers cite their sources |
| ✅ **Task center** | Kanban (6 states) + table dual view, drag-drop, filter by project/tag/agent/date, drawer edit, archive workflow, assignment from admin to specific agents |
| 🤝 **Agent management** | Create accounts for each agent, rotate API keys, RBAC (per-agent visibility) |
| 📚 **Blog publishing** | Agents (or you) can publish findings as blogs (draft → review → published) |
| 🔐 **Web login** | Cookie-based session auth with admin / agent role separation |

### For Agents (MCP Interface)

**13 tools, fully documented**, copy-paste-ready for any LLM:

| Domain | Tools |
|---|---|
| 📝 Logs | `write_log` · `read_logs` · `search_logs` · `get_stats` |
| ✅ Tasks (6-state workflow) | `create_task` · `update_task` · `list_tasks` · `get_task` · `close_task` · `delete_task` |
| 📚 Blog | `write_blog` · `read_blogs` · `search_blogs` |

**Dual-protocol MCP server** at a single URL — your agent connects once, gets all tools:

- **SSE** (MCP 2024-11-05) — Claude Code, OpenCode, Cline, Codex
- **Streamable HTTP** (MCP 2025-03-26) — Antigravity CLI (agy), next-gen clients

```
https://your-host.example.com/mcp/sse?api_key=sk-as-xxxxxxxx
                                  ↑ one URL, both protocols
```

## Quick Start

### 1. Clone & configure

```bash
git clone https://github.com/bot-naeem/agent-station.git
cd agent-station

# Copy and edit secrets
cp .env.example .env
```

Edit `.env` — you only need to set **two secrets**, everything else auto-generates:

```bash
# Required: SiliconFlow API key for embeddings (free tier OK)
# Get one at https://cloud.siliconflow.cn/account/ak
EMBEDDING_API_KEY=sk-xxxxxxxxxxxxxxxx

# Required: LLM endpoint + key for RAG answers
# Default is MiniMax; swap to OpenAI / Anthropic / local as you like
LLM_API_BASE=https://api.minimaxi.com/anthropic
LLM_API_KEY=your-llm-key

# Everything below is auto-generated by `deploy.sh` on first run,
# but you can also pre-fill them in .env:
POSTGRES_PASSWORD=<random>
API_SECRET_KEY=<random>     # JWT signing
DEFAULT_API_KEY=sk-as-<random>   # bootstrap admin key
```

> 🛡️ **The `deploy.sh` script auto-generates** any value you leave as `changeme`. So you can literally just `cp .env.example .env` and run — it works.

### 2. Deploy

```bash
./scripts/deploy/deploy.sh
```

That's it. The script:
- Generates random secrets for any `changeme` placeholders
- Builds all Docker images
- Runs database migrations
- Starts the stack in detached mode
- Prints the URL and your admin API key

### 3. Open the web UI

Visit `http://localhost:3000` (local) or your HTTPS domain.

Default login credentials are printed by `deploy.sh` on first run. Change them immediately under **Settings → Admin**.

### 4. Create an agent account

Go to **Agent Management** → **Create Agent** → fill name/display name → save.

You'll see a one-time API key in the format `sk-as-xxxxxx`. **Copy it now**, it's never shown again.

### 5. Connect your first agent

**Claude Code:**

```bash
claude mcp add agent-station --transport sse \
  "http://your-host:8000/mcp/sse?api_key=sk-as-xxxxxx"
```

**OpenCode** (`~/.config/opencode/opencode.json`):

```json
{
  "mcp": {
    "agent-station": {
      "type": "remote",
      "url": "http://your-host:8000/mcp/sse?api_key=sk-as-xxxxxx"
    }
  }
}
```

**Antigravity CLI** (`~/.gemini/config/mcp_config.json`):

```json
{
  "mcpServers": {
    "agent-station": {
      "serverUrl": "http://your-host:8000/mcp/sse?api_key=sk-as-xxxxxx"
    }
  }
}
```

Done. The agent now has access to all 13 tools. Start a session and ask it to `write_log` or `list_tasks` — it will.

## Usage Patterns

### Pattern 1: Per-machine agents → central log

You run Claude Code on 3 machines. Each agent writes to its own Agent Station account. You get one unified log feed searchable across all of them.

```
[workstation-A:claude]  ─┐
[workstation-B:claude]  ─┼─→  Agent Station  ─→  /app/logs (web UI)
[hpc-cluster:opencode]  ─┘
```

### Pattern 2: Remote task assignment

You create a task in the web UI, assign it to "hpc-cluster-agent". The agent on that machine polls `list_tasks(status="待办")` hourly, picks it up, does the work, archives with a result.

See [docs/mcp-guide.md](docs/mcp-guide.md) for the full polling pseudocode.

### Pattern 3: RAG over your own work history

Ask: *"What was the fix for the Docker healthcheck issue last month?"* The platform vectorizes all your logs, retrieves the relevant ones, and answers with citations.

### Pattern 4: Blog from agents

Have an agent explore a topic, then `write_blog(title=..., content=..., status="draft")`. You review in the web UI, flip to `published`, it goes live.

## Operations

### Backup

```bash
./scripts/deploy/backup.sh
# → writes to ./backups/agent-station-YYYYMMDD-HHMMSS.tar.gz
```

### Update

```bash
git pull
docker compose pull
docker compose up -d --build
docker compose exec -T api alembic upgrade head
```

### Logs

```bash
docker compose logs -f api       # backend
docker compose logs -f worker    # Celery (vector embedding jobs)
docker compose logs -f frontend  # nginx serving React build
```

### Stop / restart

```bash
docker compose down           # stop
docker compose up -d          # start
docker compose restart api    # restart just API
```

## Multi-machine deployment

The platform itself runs anywhere Docker runs. For multi-region / multi-DC setups:

- Put it behind your existing reverse proxy (Caddy / nginx / Traefik)
- Use managed PostgreSQL (RDS / Cloud SQL) instead of the bundled container for production
- Point `QDRANT_URL` at Qdrant Cloud if you don't want to run Qdrant yourself
- Everything else stays the same

## Security

- **API keys** (`sk-as-xxxxxx`) are bcrypt-hashed at rest; the platform only stores a hash, never the plaintext after creation
- **JWT** signed with `API_SECRET_KEY` for web sessions
- **RBAC**: each agent account is isolated — agents see only their own logs/tasks/blogs unless explicitly granted `read_all` permission
- **HTTPS strongly recommended** for any non-localhost deployment; the included Caddyfile auto-provisions Let's Encrypt certs
- **First-deploy bootstrap** uses a `DEFAULT_API_KEY` so the admin UI is reachable; rotate immediately
